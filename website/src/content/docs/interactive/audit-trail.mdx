The signer writes an issuance audit record for each signing attempt and each terminal outcome. A record joins a certificate serial or fingerprint to the PodCertificateRequest and the pod that requested it.

This page explains the records visually. <a href={guide}>The Auditing guide</a> has the configuration, the limits and the full rules.

:::note[Best-effort, by design]
The signer gets no acknowledgement that a collector stored a line. A delivered certificate can have no stored record, or only its `signed` record. Use the API server audit log as the second trail.
:::

## One request, several records

Only the leader replica signs. It writes `signed` before the status write, then one follow-up record after the write. A denied or failed request has no certificate, so it has no `signed` record.

## What a record holds

The `signed` record carries every group. Follow-up records carry the request identity, the serials and the fingerprint only. A serial is unique only within one issuer, so scope a serial query by `issuer.fingerprint`.
